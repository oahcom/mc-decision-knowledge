# 来源采集与合规规范

本规范适用于所有执行来源采集的模型或脚本。

## 允许

- 公开网页、公开文档、公开仓库、公开 issue 和公开讨论。
- 平台官方 API 或官方搜索入口。
- 搜索结果摘要作为候选线索，但正式知识必须回读原始来源。
- 少量短摘录用于证据记录，通常不超过 1200 字符。

## 禁止

- 绕过登录、验证码、付费墙、速率限制或访问控制。
- 忽略 robots.txt、服务条款或平台 API 限制。
- 采集私人信息、私人群组内容或未公开联系方式。
- 高频请求、分布式规避限流或伪装身份。
- 大段复制第三方内容；本项目保存的是决策知识摘要和证据引用，不是资料镜像。

## 来源可靠性分级

| 等级 | 定义 | 示例 |
|---|---|---|
| A | 官方文档、权威 Wiki、维护良好的核心开源仓库、论文与基准 | Minecraft Wiki 协议文档、PrismarineJS、MineDojo |
| B | 有维护记录和测试的项目、官方账号发布的技术说明 | Mindcraft、维护中的插件仓库 |
| C | 高信号公开讨论、issue、社区总结，需二次确认 | GitHub issue、Reddit 技术帖 |
| D | 单条社交帖、视频片段、无代码或无验证的说法 | 论坛个人经验、短视频 |

D 级来源只能生成 `draft` 和 `low` 置信知识，不能单独支撑 `source_verified`。

## 采集流程

1. 从 `sources/` 读取现有来源，避免重复。
2. 使用公开搜索或官方 API 找到候选来源。
3. 回读原始页面或仓库，确认内容、版本和许可证。
4. 写入或更新一个来源 JSON 文件。
5. 记录短摘录和证据说明，不保存无关个人信息。
6. 在批次报告中列出新来源、放弃来源和原因。
